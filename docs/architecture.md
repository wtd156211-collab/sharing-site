# 系统架构决策

## 已确认

| 项目 | 决策 | 依据 |
| --- | --- | --- |
| 部署目标 | Ubuntu 云服务器，使用 Docker Compose | 已连接服务器并确认 Docker 26.1.3、Compose v2.27.1 |
| 数据库 | MySQL | 用户确认；项目已有 Drizzle MySQL 方言和 mysql2 依赖 |
| 应用形态 | Node.js + TypeScript 单体应用 | 与现有 Express/Vite 骨架一致，降低部署复杂度 |
| 实时更新 | SSE | 满足在线页面接收笔记和评论更新的需求 |
| 管理认证 | 默认复用现有 Manus OAuth，权限由 `users.role` 控制 | 避免在第一版引入另一套账号体系 |

开发、测试和 Docker Compose 验证全部先在本地完成；目标云服务器只在完整验收通过后执行最终部署。部署使用独立 Compose 项目、容器、数据卷和 Nginx 子域名，不停止现有应用。

## 待确认

| 项目 | 当前处理 | 影响 |
| --- | --- | --- |
| 域名 | 先按 `APP_BASE_URL` 配置，不写死域名 | 决定 Caddy HTTPS 配置 |
| 图片存储 | 支持 `local` 和 S3；单服务器默认示例为 `local` | 决定备份目标和数据卷 |
| 分享密码 | 由空间设置可选 | 决定分享访问会话流程 |
| 匿名评论 | 由空间设置控制 | 决定评论限流和设备会话策略 |

## 接口边界

产品业务接口使用文档约定的 REST 路径（`/api/admin/*`、`/api/share/*`、`/health`）。现有 `/api/trpc` 保留给 Manus OAuth 和系统兼容路由，不把数据库内部字段直接返回给浏览器。

## 数据与隐私

分享令牌使用高熵随机值，数据库只保存哈希；图片下载使用权限检查和短期签名地址；评论按纯文本显示；日志必须脱敏。生产密钥只通过环境变量或服务器密钥管理注入。
