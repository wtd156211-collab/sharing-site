# 家庭笔记分享网站 Material 3 UI 设计规范

**状态：已获用户确认，待进入实施计划。**

## 1. 目标与范围

为家庭笔记分享网站统一建立一套简洁、商务、Google Material 3 风格的界面。此次覆盖管理后台首页、空间设置、分享页、现有 AI 聊天组件，以及共用的弹窗、上传、通知和表单状态。

此次是视觉与交互层改造，不改变既有路由、REST 接口、MySQL 数据模型、分享访问控制或实时同步逻辑。AI 聊天组件只改造视觉与交互状态，不新增 AI 路由、模型调用或后端能力。

## 2. 设计方向

拒绝纯白背景、高饱和蓝色按钮和相同卡片重复堆叠的模板化后台。整体使用冷灰蓝工作区、层级明确的近白内容面板和克制的钴蓝主操作色；家庭照片和笔记作为内容本身保留温度，但不再依赖大面积暖色装饰或杂志式衬线标题。

- 风格：Google Material 3 的清晰层级、柔和表面、明确状态与低干扰反馈。
- 色彩：钴蓝 `#2D5BD8` 为唯一品牌操作色；语义色独立处理，不作为品牌装饰。
- 中性色：冷灰蓝色阶，页面与面板均使用带色相的近中性颜色，不使用纯白或纯黑。
- 字体：Roboto 优先，标题、正文与数字使用同一理性无衬线体系；元数据可使用等宽字体。
- 圆角：内容卡片 16px，小型控件与输入框 12px；不使用过度胶囊化布局。
- 阴影和边界：浅色、带墨色倾向的轻阴影与低对比边界，只用于建立层级。
- 动效：仅包含按钮按压、抽屉、弹窗、骨架屏和数据状态变化等反馈；不使用滚动特效或装饰性动画。
- 图片：不新增生成或下载的视觉图片；图片区域只显示用户上传的家庭照片和已有内容。

## 3. 信息架构与页面行为

### 3.1 管理后台壳层

- 桌面端保留 240px 固定左侧导航，导航自身在内容超出高度时独立滚动。
- 导航按“主要功能、空间设置、账户”分组，选中态使用低饱和蓝色背景与钴蓝图标。
- 主内容区使用 64px 顶部应用栏承载页面标题、当前空间状态和页面操作；内容区域自适应宽度。
- 移动端隐藏侧栏，使用固定顶部应用栏；不为分享阅读页添加后台导航。

### 3.2 首页

- 首屏为“今日概览”：标题、空间状态和唯一的主操作“新建笔记”。
- 笔记流是主信息区；分享状态、最近动态和图片记忆为辅助信息区。
- 桌面端采用主内容加辅助栏的两列结构，平板和手机收敛为单列。
- 统计内容必须绑定真实数据；加载时使用与最终布局一致的骨架屏，空数据时给出下一步操作，不展示模拟统计数字。

### 3.3 空间设置

- 设置项按“分享权限、访问密码、评论与通知”分组。
- 每项提供简短说明、当前状态和清晰的保存或撤销动作。
- 破坏性操作从常规设置中隔离，使用明确的风险说明和确认步骤。

### 3.4 分享页

- 分享页是独立阅读体验，不继承后台侧栏。
- 顶栏承载空间名称、访问状态和返回入口；正文使用居中、可阅读的时间线笔记流。
- 笔记、图片、评论和访问密码表单使用统一的 Material 3 表面、输入、错误和成功状态。

### 3.5 AI 聊天组件

- 会话区使用近白内容面板，用户与 AI 消息以对齐和浅色层级区分，不使用夸张气泡。
- 输入区固定在组件底部，发送、加载、禁用、空会话和错误状态均可识别。
- 建议问题使用小型操作卡，键盘焦点与屏幕阅读器标签保持可访问。
- 组件作为可嵌入的辅助面板保持现有能力边界，不改变其对接方式。

## 4. 组件与状态标准

| 组件 | 规范 |
| --- | --- |
| 主按钮 | 钴蓝填充、近白文字、最小 44px 触控高度；按压和禁用状态清晰。 |
| 次按钮 | 近白表面与低对比边界，不与主按钮竞争。 |
| 输入框 | 标签始终可见；支持默认、悬停、聚焦、错误、成功和禁用状态。 |
| 卡片 | 用于真实内容分组，不将每一行都包入卡片；统一 16px 圆角与轻阴影。 |
| 通知 | 成功、失败和提示采用语义色，消息说明结果与可执行的下一步。 |
| 加载与空状态 | 骨架屏保留布局；空状态包含原因、下一步说明和适当操作。 |
| 导航 | 文本和图标同时出现；桌面端固定，移动端不产生横向溢出。 |

## 5. 可访问性与响应式要求

- 文字与背景至少达到 WCAG AA 对比度；占位符、帮助文本和焦点环同样纳入检查。
- 所有可操作控件可通过键盘访问，并有可见焦点状态。
- 所有移动端触控目标至少 44px；按钮、标签和导航项不换行。
- 测试 320px、375px、414px、768px 和桌面视口；图片网格使用可收缩轨道，不产生横向滚动。
- 保持一个顶层粘性导航定位规则，避免和其他粘性元素冲突。
- 尊重 `prefers-reduced-motion`，反馈动效在减弱动态模式下立即呈现终态。

## 6. 实施边界与验证

### 修改范围

- `client/src/index.css`：设计 token、全局表面、排版、响应式与状态样式。
- `client/src/components/NotesShell.tsx`：后台壳层、导航与顶部应用栏。
- `client/src/pages/AdminDashboard.tsx`、`Settings.tsx`、`ShareSpace.tsx`：页面结构和组件语义。
- `client/src/components/AIChatBox.tsx`：AI 组件的 Material 3 视觉状态。
- 相关测试：固定导航、页面状态和可访问性约束的回归检查。

### 不修改范围

- Express 路由、认证、分享访问规则、SSE、文件存储、MySQL schema 和 Docker 部署配置。
- AI 模型调用、AI 入口路由和服务端业务能力。

### 验收标准

1. 全站使用统一的钴蓝与冷灰蓝 token，且不存在无理由的第二品牌色。
2. 桌面端左侧导航保持固定，右侧内容滚动不影响导航位置。
3. 首页、设置、分享页、弹窗和 AI 组件在视觉、按钮、输入和反馈状态上保持一致。
4. 真实数据缺失时显示空状态或骨架屏，不展示模拟业务统计。
5. 测试、TypeScript 检查和生产构建通过；关键桌面和移动视口可正常使用。
